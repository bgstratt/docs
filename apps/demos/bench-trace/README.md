# Bench trace demo

## Purpose

In-browser engine benchmark: replays the automerge-perf **B4 editing trace**
(259,778 single-character edits producing a 104,852-char LaTeX paper) through
the NodalMerge WASM engine, with a live ops/sec meter and a **SHA-256
convergence check** against the expected final text.

- **Fully client-side** — the doc is created with `autoConnect: false` and
  never dials a server; repeat runs and bot traffic create zero host load.
- **Run guard** — state machine `idle → loading-trace → running → done`; the
  Run button is disabled while a run is in flight.
- Two slices: a 50k-op quick run (default) and the full 260k-op trace, both
  fetched on demand and cached in memory.
- NodalMerge-only numbers: no competitor comparisons; UI copy notes that
  browser/WASM throughput differs from native engine throughput.

## Trace assets

`public/b4-trace-{50k,full}.json` + `public/b4-trace-meta.json` (expected
opCount / finalLength / finalSha256 per slice) are generated by
`scripts/gen-bench-trace.mjs` at the docs repo root, which reads
`../nodalmerge/benchmarks/data/b4-editing-trace.json` and validates its own
replay against the trace's `finalText` before writing. Regenerate only when
the source trace changes.

## Run locally

`npm install`, `npm run dev` (no demo host needed). `npm test` covers the
progress math; convergence itself is asserted at runtime by the hash check.
